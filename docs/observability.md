# Observability

## Stack Overview

| Component | Role | Port |
|---|---|---|
| **Prometheus** | Scrapes `/metrics` endpoint every 15s | 9090 |
| **Tempo** | Receives OTLP gRPC traces | 4317 |
| **Loki** | Receives structured JSON log push | 3100 |
| **Grafana** | Unified dashboards, alerting, exemplar links | 3000 |

## Key Metrics

| Metric | Type | Labels | Description |
|---|---|---|---|
| `http_requests_total` | Counter | `method`, `path`, `status_code` | Total HTTP request count |
| `http_request_duration_seconds` | Histogram | `method`, `path` | HTTP request latency |
| `active_requests` | Gauge | — | In-flight requests |
| `rag_queries_total` | Counter | `collection_name`, `status` | RAG query count by status |
| `rag_query_duration_seconds` | Histogram | `collection_name` | End-to-end RAG query latency |
| `rag_retrieval_duration_seconds` | Histogram | `collection_name` | Vector retrieval latency |
| `rag_generation_duration_seconds` | Histogram | `model` | LLM generation latency |
| `embedding_generation_duration_seconds` | Histogram | `provider`, `mode` | Embedding generation latency |
| `ingestion_jobs_total` | Counter | `source_type`, `status` | Ingestion job count by status |
| `cache_operations_total` | Counter | `operation`, `cache_type`, `result` | Cache hit/miss counts |
| `cache_operation_duration_seconds` | Histogram | `operation`, `cache_type` | Cache operation latency |
| `database_queries_total` | Counter | `operation`, `table` | DB query count |
| `database_query_duration_seconds` | Histogram | `operation`, `table` | DB query latency |
| `database_pool_size` | Gauge | — | Configured pool size |
| `database_pool_checked_out` | Gauge | — | Active DB connections |

## PromQL Examples

**Request rate (last 5 minutes):**
```promql
rate(http_requests_total[5m])
```

**Error rate:**
```promql
rate(http_requests_total{status_code=~"5.."}[5m]) / rate(http_requests_total[5m])
```

**RAG query p95 latency:**
```promql
histogram_quantile(0.95, rate(rag_query_duration_seconds_bucket[5m]))
```

**Cache hit rate:**
```promql
rate(cache_operations_total{result="hit"}[5m]) / rate(cache_operations_total[5m])
```

**Slow DB queries (>100ms):**
```promql
rate(database_query_duration_seconds_bucket{le="0.1"}[5m])
```

## Grafana Dashboards

All dashboards are auto-provisioned at startup from `grafana/provisioning/dashboards/json/`.

| Dashboard | UID | Contents |
|---|---|---|
| **RAG Pipeline Performance** | `rag_pipeline` | Query rate by status, end-to-end latency P50/P95/P99, retrieval vs generation breakdown, embedding latency, LLM cache hit rate |
| **API Performance** | `api_performance` | Request rate by endpoint, P95 latency per route, HTTP status distribution, active requests, error rate, top 10 slowest endpoints |
| **Database & Cache** | `db_cache` | Query rate by operation, query latency P95 by table, connection pool utilization, Redis cache hit rate by type, operation latency |
| **System Overview** | `system_overview` | Service health, ingestion job rate by source type, active users, cache size |
| **Error Tracking** | `error_tracking` | Error rate by endpoint and status code, ingestion failure rate, embedding/LLM error alerts |

Access Grafana at `http://localhost:3000` (default credentials: `admin` / `admin`).

## Alert Rules

Alert rules are defined in `prometheus/alerts/rag_alerts.yml`.

| Alert | Threshold | Severity | Description |
|---|---|---|---|
| `HighErrorRate` | error rate > 5% for 5m | critical | API returning too many 5xx errors |
| `HighLatency` | p95 > 10s for 5m | warning | RAG queries taking too long |
| `LowCacheHitRate` | hit rate < 50% for 15m | warning | Cache not providing enough benefit |
| `SlowDatabaseQueries` | p95 > 500ms for 5m | warning | Database queries degraded |
| `IngestionFailures` | failure rate > 10% for 10m | critical | Ingestion pipeline failing |

## Trace and Log Correlation

Every request carries:
- **`X-Trace-ID`** response header — OpenTelemetry trace ID (32 hex chars)
- **`X-Span-ID`** response header — current span ID (16 hex chars)
- **`X-Request-ID`** response header — UUID generated by `RequestContextMiddleware`

Structured log entries include `trace_id` and `span_id` fields (injected by `add_trace_context()` processor). In Grafana, use the **Explore** view with Loki, filter by `trace_id`, then click the **Tempo** exemplar link to jump directly to the trace.

## Troubleshooting

**Grafana shows no data:**
- Verify Prometheus is scraping: `http://localhost:9090/targets`
- Confirm `ENABLE_METRICS=true` in `.env`
- Check that the `rag-app` service is reachable from the Prometheus container

**No traces in Tempo:**
- Confirm `ENABLE_TRACING=true` and `OTLP_ENDPOINT=http://tempo:4317` in `.env`
- Check Tempo logs: `docker compose logs tempo`

**No logs in Loki:**
- Confirm `LOKI_ENABLED=true` and `LOKI_ENDPOINT=http://loki:3100`
- Verify `python-logging-loki` is installed (`pip install python-logging-loki`)
- Check Loki logs: `docker compose logs loki`

**Redis cache not working:**
- Confirm `REDIS_ENABLED=true` and Redis is running: `docker compose ps redis`
- The application degrades gracefully — cache misses are logged as warnings
